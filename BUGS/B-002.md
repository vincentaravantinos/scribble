# B-002: Scribble no longer erases after sn-plugin-lib 0.2.3 upgrade

- **Status**: Fixed — reverted to sn-plugin-lib 0.1.65 (DECISIONS.md
  2026-10-12); confirmed on-device on the A5X (erase, collateral bound, Undo,
  no false positives). PEN_UP/getElements frame mismatch reported to Ratta.
- **Symptom**: With the CR-005 build (sn-plugin-lib 0.2.3) on an A5X
  (firmware Chauvet.D102.2610091001), scribbling over a word does nothing —
  neither the word nor the scribble is erased.
- **Hypothesis**: The plugin's JS isn't running at all, rather than the
  coordinate change computing a wrong lasso rect. Logcat since boot
  (10:59) has no `[Scribble] PEN_UP listener registered` line — that log in
  `index.js` is ungated (not behind `DEBUG`) and fires on every bundle load —
  while another plugin (TermDefinition) logs normally in the same buffer.
  Either the new .snplg wasn't installed/enabled, or the 0.2.3 bundle fails to
  load before `index.js` runs.
- **Evidence**: `adb logcat -d` — zero `[Scribble]` lines, no ReactNativeJS
  errors; `/sdcard/MyStyle/scribble.snplg` pushed 11:22.
- **Update**: install was indeed missing at first; after installing, the
  plugin loads (registration line logged, FILE:READ granted) and receives
  strokes, but still doesn't erase and no "Working…" overlay appears — so the
  stroke is rejected before `eraseByScribble` (classification, orientation or
  file/page). Suspects: empty points, or points not in the expected px scale
  (e.g. still EMR → diagonal over the new 1420 cap).
- **Trace (11:39, instrumented build)**: host logs `reportSdkVersion:0.2.3`
  (it knows the plugin is on the new lib), yet PEN_UP stroke points are still
  **EMR**: x=[15336,19578] y=[1374,12739], element maxX=20967 maxY=15725 (A5X
  page is 1404×1872 px). The real scribble measured conc=0.97 rev=12 (passes)
  but diag=4772 > the new 1420 px cap → classified normal → no erase.
- **Revised hypothesis**: on this firmware the PEN_UP payload is not converted
  to px for 0.2.x plugins (the release's API list covers getElements/lasso
  etc., not the PEN_UP event). Unknown yet whether `getElements` returns px —
  if it does, the scribble (EMR) and page strokes (px) are in different
  frames and the crossing test breaks too.
- **Instrumentation**: `DEBUG = true`; checkpoints in `src/logic/scribble.ts`
  — A (PEN_UP payload), B (point count, first/last, x/y range, maxX/maxY),
  existing STROKE line (conc/rev/diag), C (classified scribble), D (erase start),
  E (per stroke: `getPageSize` + `getElements` last stroke's point range/maxX/maxY).
  Firmware confirmed 2.27.42 by the user.
- **Trace (11:53, checkpoint E)**: same scribble — PEN_UP points EMR
  (diag 4966), `getElements` last stroke (456 pts) in **px**: x=[855,1232]
  y=[1453,1687] within pageSize 1404×1872. **Confirmed: mixed frames** on
  2.27.42 + 0.2.3 — PEN_UP payload EMR, `getElements` px. Also: this A5X's
  EMR max is 20967×15725 (ratio 11.2 px→EMR), not the lib table's 15819 —
  EMR/px ratio is device-dependent (Manta 8.45), so the corpus *was* A5X.
- **Next step**: none. Retry 0.2.x under CR-005 once Ratta fixes PEN_UP.
