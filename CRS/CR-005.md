# CR-005: Adopt sn-plugin-lib 0.2.x unified (Android pixel) coordinates

**Status:** Blocked — on Ratta. The 0.2.3 implementation was reverted
(B-002): on 2.27.42 the PEN_UP payload is still EMR while `getElements`
is px. SPEC.md REQ-100…230 (added in Feature step 1, approved) stay. Resume
at Feature step 5 once Ratta fixes PEN_UP; make the diagonal cap relative to
the page size (EMR/px ratio differs per device — DECISIONS.md 2026-10-12).

## Impact analysis

**High impact — escalate to Feature.**

There are no new user-facing requirements, but the upgrade changes the units of
every coordinate Scribble touches, across several files:

- `erase.ts` / `geometry.ts`: the EMR→screen conversion (`emrBboxToScreenRect`,
  `emrBboxToAndroidRect`, the `maxX`/`maxY` scaling) goes away. The bbox is
  already in pixels and feeds `lassoElements` directly (pad + integer-round
  only). This is a net code deletion.
- `constants.ts`: `MAX_BBOX_DIAGONAL = 12000` is in EMR units and has to be
  rescaled to pixels (~8× smaller). Concentration, reversals, the deadband and
  the crossing test are scale-invariant.
- `__tests__/fixtures/scribble-corpus.json` is recorded in EMR units. Either
  rescale it or re-record it so the detection tests stay meaningful.
- SDK_DOC.md: the EMR-conversion entries become legacy-only for ≤0.1.65.

Optional follow-up, not in this CR: the deprecated EMR mapping was one of the
two landscape blockers (DECISIONS.md 2026-06-17). Once on 0.2.x, re-test
landscape erase. The `lassoElements` hang is a separate blocker and may still
apply.

## Request

Update Scribble for the Chauvet 3.30.45 (Manta/Nomad) / 2.27.42 (A5X/A6X)
plugin release, which ships `sn-plugin-lib` 0.2.3. All plugin coordinates
(stroke sample points, `getElements`, `lassoElements` rects, etc.) become
Android pixel coordinates based on `PluginFileAPI.getPageSize`; the EMR
converters (`PointUtils.emrPoint2Android`, element `maxX`/`maxY`) are
deprecated. Plugins built on 0.1.65 or earlier (Scribble today) keep working
unchanged.
