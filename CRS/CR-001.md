# CR-001: Upgrade sn-plugin-lib + declare plugin permissions

**Status:** Done

## Impact analysis

**High impact — escalate to Feature.**

The `sn-plugin-lib` version bump itself is mechanical. But the permission
half is not: per `docs.supernote.com/en/plugin-base/permission.md`, four
permissions exist (`plugin.permission.FILE:READ/WRITE/DELETE/INTERNET`),
guarding different SDK calls, declared via `PluginConfig.json`'s
`uses-permissions` array, and requested at runtime via
`PluginManager.hasPermission`/`requestPermission` — which shows a native
OS dialog to the user ("Allow this time only" / "Always allow" / "Don't
allow"), already documented in `SDK_DOC.md`'s "Runtime permissions"
section from prior work.

Scribble currently requests no permissions at all. Design decisions
needed before implementation: exactly which permission(s) erase-by-scribble
needs (the docs summary is inconsistent about whether element deletion
needs FILE:WRITE or FILE:DELETE — needs on-device confirmation via error
code 1500/1501-style diagnostics, not guessed), when in the flow to
request it (first scribble? plugin install? every launch?), and what
erase-by-scribble should do if the user denies — none of this is a single
well-understood call site, so it doesn't qualify as low impact.

## Request

Update Scribble's `sn-plugin-lib` dependency (currently pinned `^0.1.43`) to
the latest version, per the Chauvet 3.29.43 Beta (Manta/Nomad) / 2.26.40 Beta
(A5X/A6X) plugin preview release. That release also adds a plugin permission
system — plugins must declare the permissions they need (e.g. Read Files /
Modify Files), granted by the user under Settings → Plugins → Permissions.

Without this update, Scribble will not run at all on the new firmware
(the release notes state plugins on old dependency versions are refused).

Source: r/Supernote_dev, "Plugin Preview Build: Chauvet 3.29.43 Beta for
Manta / Nomad and Chauvet 2.26.40 Beta for A5X / A6X" (u/Dunn-sn).
