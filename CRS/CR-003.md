# CR-003: Fix 1-indexed page/element indices

**Status:** Analyzed

## Impact analysis

**Low impact — fast-track.**

Grepped the codebase for every API the release notes list as newly
1-indexed: `getElement`, `getElementNumList`, `deleteElements`,
`insertPageElements`, `deletePageElements`, `modifyPageElements`,
`batchUpdatePageElements`, `numInPage` — zero matches. Scribble only uses
`getElements` (plural, page-level listing) and `getPageSize`, neither of
which the release notes name as changed, with `page` sourced from
`getCurrentPageNum()` (also not in the changed list).

Single well-understood conclusion, no design decisions — fast-track to
on-device verification rather than a full plan. Likely closes as "not
applicable" once confirmed on-device.

## Request

As of the Chauvet 3.29.43 Beta / 2.26.40 Beta SDK release, element page
indices (`numInPage`) and related page-index parameters (`getElement`,
`getElementNumList`, `deleteElements`, `insertPageElements`,
`deletePageElements`, `modifyPageElements`, `batchUpdatePageElements`) are
now consistently 1-indexed. Previously the indexing convention differed.

Need to audit Scribble's page-index usage — `src/logic/erase.ts` passes a
`page` value into `PluginFileAPI.getElements`/`getPageSize`, and any other
call sites that consume/produce page or element indices — against the new
1-indexed convention, and fix accordingly.

Manta / Nomad and Chauvet 2.26.40 Beta for A5X / A6X" (u/Dunn-sn), API
