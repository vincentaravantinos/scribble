# CR-002: Fix lassoElements out-of-bounds failure

**Status:** Done

## Impact analysis

**Low impact — fast-track.**

Read `src/logic/erase.ts` and `src/utils/geometry.ts`. The lasso rect is
already run through `padRect(raw, LASSO_PAD_PX, pageSize.width - 1,
pageSize.height - 1)` (`erase.ts:117`), which clamps `left`/`top` to `>= 0`
and `right`/`bottom` to `<= pageSize.width - 1` / `pageSize.height - 1`
(`geometry.ts:235-242`) unconditionally, regardless of the input box. So
the rect handed to `lassoElements` should already be fully within page
bounds under the new constraint — no code change appears necessary.

This is a single well-understood call site with no new requirements or
design decisions — fast-track to on-device verification (Implementation
step 4 onward) rather than a full plan.

## On-device confirmation

Scribbled and erased right at a page edge on the Chauvet 3.29.43 build:
`lassoElements` succeeded (no `lassoElements failed` in the log),
`deleteLassoElements` succeeded (`deleted=4 crossed=3 success=true`). No
code change needed. Added REQ-060 (SPEC.md) and TC-004 (TEST_CASES.md) as
a standing regression test, since this is exactly the kind of corner case
a future SDK change could reopen silently.

## Request

As of the Chauvet 3.29.43 Beta / 2.26.40 Beta SDK release, `PluginCommAPI.lassoElements`
now requires the given rect to be fully within page bounds — the call fails
if it goes out of bounds. Previously it did not enforce this.

Scribble's erase logic (`src/logic/erase.ts:120`) calls `lassoElements`
directly with a rect derived from the scribble gesture's bounding box. A
scribble drawn near a page edge can now push that rect out of bounds,
making erase fail where it used to succeed.

Need to clamp/adjust the lasso rect to stay within page bounds so
edge-drawn scribbles keep erasing correctly.
